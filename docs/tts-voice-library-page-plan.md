# Astra 音色库页面方案

> 更新时间：2026-10-01
> 状态：产品与前端交互方案，尚未实现

## 1. 目标与边界

本方案把已有的 TTS 音色库、授权、版本和 IndexTTS 快照能力转化为可被实际用户使用的网页工作流。

音色库回答的是“**Astra 应以谁的声音说话**”；会议声纹回答的是“**录音中是谁在说话**”。两者必须在信息架构、数据和交互上保持分离，不能将会议声纹档案自动转为可合成音色。

首期目标：

- 用户能创建、试听、授权、启用和停用本地合成音色；
- 用户能在实时助手开始前选择明确的 `voice_id + voice_revision`；
- 选择后整个会话固定使用同一音色版本，并在会话中可见；
- 模型、音色或授权不可用时，用户能理解原因并切换到系统默认 TTS。

非目标：

- 不提供公开分享、多人协作或跨设备同步音色；
- 不把任意录音自动转换为可用克隆音色；
- 不在首期开放未经验证的第三方生成参数；
- 不以硬删除取代归档和授权撤销。

## 1.1 实现前决策：TTS 运行时策略

当前运行时每个进程只构造一个由 `TTS_BACKEND` 决定的 TTS client。因此，“系统默认 Piper”和“IndexTTS 音色”不能在当前架构中同时作为同一会话选择器的可用项。

已决策采用**多引擎路由**。完整运行时边界见 [多引擎 TTS 路由设计](tts-multi-engine-router-design.md)。

该决策曾评估以下两种策略：

1. **单引擎 MVP（推荐）**：一个部署实例只有当前 TTS backend 可用于会话；音色库可管理全部资产，但实时选择器只显示与当前 backend 兼容且引擎已就绪的音色。“系统默认”表示当前 backend 的默认声音，而不是保证为 Piper。
2. **多引擎路由**：实现受控 TTS router，同时管理 Piper 与 IndexTTS 等客户端，并按会话快照选择引擎。此方案需要独立处理模型内存、队列、回退、健康检查和关闭生命周期，不属于首期 UI 工作。

在 `TTS-00A` 路由实现完成前，前端仍按当前单引擎能力显示音色；不得提前展示跨引擎可选项。

## 2. 当前基础与体验缺口

后端已有 `TtsVoiceStore`、参考音频版本、授权状态、激活/归档/撤销、`voice_id + voice_revision` 快照，以及可选的 `indextts_mlx` 后端。WebSocket `start_session` 也支持接收音色快照。

但当前网页没有音色库路由、导航入口、试听入口或实时会话音色选择器；实时助手建立会话时也没有传入 `voice_id` 与 `voice_revision`。因此，音色库和 IndexTTS 的后端能力尚未形成用户可完成的产品链路。

真实 IndexTTS MLX 的目标设备 L2 推理验收尚未通过，故它在首期应显示为“实验性”，不可替代 Piper 等稳定回退路径。

## 3. 信息架构

在主导航新增一级工作区：

```text
实时助手
音频工作台
会议复核
模型训练
音色库                 ← 新增
管理设置
```

音色库内部结构：

```text
音色库
├── 音色列表
│   ├── 搜索、状态和引擎筛选
│   ├── 音色卡片
│   └── 新建音色
└── 音色详情（抽屉或独立详情页）
    ├── 当前版本与参考音频
    ├── 授权状态
    ├── 试听合成
    ├── 版本历史
    └── 归档 / 撤销授权
```

## 4. 音色库主页面

页面标题为“本地音色库”，副标题说明“管理用于语音合成的参考音色；会议说话人档案仅用于识别，不会自动用于语音克隆”。

顶部控件：

- 按名称搜索；
- 状态筛选：全部、草稿、可用、已归档、已撤销；
- 引擎筛选：IndexTTS、CosyVoice、其他；
- 主操作：`新建音色`；
- 摘要状态，例如“可用 4 · 待授权 2 · 当前 TTS：IndexTTS（实验性）”。

每张音色卡片至少展示：

```text
[头像或波形]  小雅 · r3                         可用
IndexTTS · 中文 · 参考音频 9.4 秒
已确认授权 · 更新于 2026-10-01

[播放参考音频] [试听] [设为本次会话音色]
```

草稿卡片应突出下一步：“确认授权后才能启用或试听”。被撤销的音色及其所有 revision 不能播放、下载、试听或选择为会话音色，只保留必要的审计说明。

## 5. 新建音色向导

采用四步向导，逐步解释约束，避免用户在一次表单中面对大量技术字段。

### 第一步：基本信息

- 音色名称；
- 目标引擎，默认 IndexTTS；
- 语言，默认中文。

### 第二步：上传参考音频

- 支持拖放和文件选择；
- 说明推荐条件：5–15 秒、单人、安静环境、自然语速；
- 首期如仍仅支持 WAV，必须在文件选择前明确写出“当前仅支持 WAV”，不能在上传失败后才告知；
- 上传完成后展示时长、采样率、声道、文件大小、波形预览和校验结果。

### 第三步：授权确认

授权不应只是普通复选框，而应明确说明：

> 我确认拥有使用该录音创建和使用合成音色的授权；撤销后，Astra 将停止新的合成请求。

用户完成显式确认后，才能激活音色或进行试听。该操作对应音色 revision 的 consent 状态。

### 第四步：试听与启用

- 提供可编辑的测试文案，默认值为“你好，我是 Astra。这是一段本地语音合成试听。”；
- 限制文案长度，避免试听任务成为长文本推理入口；
- 显示“正在加载模型 / 正在构建音色 / 正在合成 / 可播放 / 失败”等明确状态；
- 成功后提供“保留为草稿”“启用音色”“进入实时助手使用”。

试听是**强烈推荐的预检**，但不是激活的硬性前置条件：模型未部署或尚未通过设备验证时，管理员仍可完成资料入库、授权和激活。此时音色应显示“已启用，当前引擎未就绪”，且不能用于实时会话。界面要提供“跳过试听并启用”，并说明启用不代表已验证可合成。

## 6. 音色详情与版本管理

详情页首屏按用户目的组织：

| 区域 | 内容 |
| --- | --- |
| 当前版本 | revision、引擎、语言、时长、创建时间 |
| 参考音频 | 播放器、质量状态、哈希摘要 |
| 授权 | 已确认/待确认/已撤销、操作时间与备注 |
| 试听 | 测试文案、生成按钮、播放器、耗时、失败原因 |
| 版本历史 | 每版参考音频、状态、创建时间、可设为当前版本 |
| 风险操作 | 归档、撤销授权；默认不提供硬删除 |

替换参考音频的操作必须命名为“创建新版本”，不得称作“覆盖上传”。应向用户明确：历史会话仍引用旧版本，新会话才会使用新版本。

## 7. 与实时助手的连接

实时助手在“开始通话”前新增“回复音色”选择器：

```text
回复音色
[系统默认（当前引擎）           v]
  系统默认 · 当前引擎的稳定声音
  小雅 · IndexTTS · r3（仅 IndexTTS 当前可用时显示）
  林先生 · IndexTTS · r1（仅 IndexTTS 当前可用时显示）
```

选择后，WebSocket 的 `start_session` 消息应携带：

```json
{
  "type": "start_session",
  "voice_id": "voice-...",
  "voice_revision": 3
}
```

会话开始后锁定此版本，并在实时页显示“当前回复：小雅 · IndexTTS · r3”。不支持克隆的引擎不得把克隆型音色显示为可选项。

若当前引擎或所选音色不可用，应在开始通话前阻止选择，说明具体原因并建议用户改选当前引擎的系统默认声音。不得在用户说完后静默合成失败。

## 8. 状态与错误设计

| 状态 | 页面行为 |
| --- | --- |
| 引擎未安装或模型未就绪 | 允许管理音色，但禁用“试听/用于会话”，展示可执行的原因说明。 |
| 音色待授权 | 可以查看元数据和参考音频；不可试听或用于实时会话。 |
| 首次模型加载 | 显示可感知的加载状态，不承诺不可靠的精确百分比。 |
| 音色构建中 | 禁止重复提交，提示首次使用该音色可能较慢。 |
| 合成失败 | 保留测试文案和音色选择，展示可复制的错误摘要和重试按钮。 |
| 已撤销授权 | 立即从选择器移除，禁止参考音频与试听音频的新下载/播放；历史记录仅保留“曾使用 rN，现已撤销”的元数据。 |
| 当前引擎不支持克隆 | 仅展示系统音色，不把克隆音色伪装成可选项。 |

## 9. API 与实现补齐

现有 `/api/tts/voices` CRUD、revision、consent、activate、archive 和参考音频下载接口可作为页面数据源。为完成完整体验，需要补齐：

```text
POST /api/tts/voices/{voice_id}/test
```

该接口应：

- 仅允许 active 且授权已确认的 revision；
- 固定使用用户指定 revision，而不是读取之后可能变化的 current revision；
- 返回可播放 WAV，并在响应中记录/回显音色版本和模型版本；
- 设置试听并发限制，满载时返回明确的 429；
- 不阻塞 ASGI 事件循环。

前端需要新增：

- `VoiceLibraryPage`；
- 音色 API client 与统一错误处理；
- 实时助手的 active voice 选择状态；
- `start_session` 的 `voice_id` / `voice_revision` 传递；
- TTS 后端和音色可用性展示；
- Piper 等默认回退入口。

## 10. 分期建议

### 第一期：安全且可使用

1. 新增“音色库”导航、列表、详情和上传流程；
2. 完成授权确认、激活、归档、撤销和参考音频播放；
3. 补齐 IndexTTS 指定 revision 的试听接口与页面；
4. 完成 TTS-00A 路由实现后，在实时助手选择音色，并传递 `voice_id + voice_revision`；
5. 显示模型可用性、失败原因和 Piper 回退；
6. 在目标 Mac 完成 IndexTTS 短句、多轮、打断和内存验收。

### 第二期：质量与效率

- 参考音频质量评分、波形与录音指引；
- 音色标签、收藏和预设；
- 受控的语速、语言等生成参数；
- 会话记录中的音色/模型快照；
- 对非 WAV 文件进行本地转码和质量检测。

## 11. 验收标准

- 用户无需调用 API 即可创建、授权、试听、启用和归档音色；
- 音色选择器只展示当前 TTS 后端实际可用、已授权的音色；
- 实时会话建立后使用固定的 `voice_id + voice_revision`；
- 新建 revision 不会改变已开始或已完成会话的音色快照；
- 授权撤销后，音色不能继续用于新的试听或会话；
- 当前引擎或音色不可用时，用户能在开始会话前看到原因并切换当前引擎的系统默认声音；
- 所有高风险操作均保留可理解的状态与审计信息；
- IndexTTS 在目标 Mac 完成真实模型验收前，始终以实验性能力呈现。
