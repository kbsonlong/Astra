## 2. 产品概述

### 2.1 产品定位

Astra 是运行在个人 Mac mini 上的本地模型会议总结助手。音频处理、语音模型、会议产物和图片产物在本机完成；会议对话和纪要生成支持使用本地 LLM，也保留现有的远程 OpenAI 兼容 LLM 配置。产品不设计账号、权限或数据隔离能力。

系统使用本地模型完成音频接收、语音活动检测、MLX ASR 转写、标点、说话人分离、语音合成和规划中的文生图；会议纪要和对话通过 OpenAI 兼容接口接入本地或远程 LLM。

产品重点是：

- 音频、文本、模型推理和结果文件全部留在本机，适合个人会议和内部资料整理；
- 同时支持实时语音对话和离线会议处理；
- 会议处理结果可追溯到原始片段、时间戳、说话人和任务日志；
- 纪要提示词可选择内置模板，也可由用户创建和编辑；
- 会议纪要可进一步生成封面、主题插图等本地图片素材。

### 2.2 要解决的问题

1. 用户希望用语音直接与本地助手交互，并尽快听到回答。
2. 用户需要把录音转换为可阅读、可复核的逐字稿。
3. 会议录音需要自动输出结构化纪要，而不是只得到一段无上下文的文本。
4. 说话人识别和自动纠错存在不确定性，需要支持人工审核和修正。
5. 团队对会议纪要结构的偏好不同，需要支持模板化和自定义提示词。
6. 会议纪要缺少可直接使用的视觉素材，需要根据会议主题或摘要生成配图。

### 2.3 产品目标

| 目标 | 目标描述 |
| --- | --- |
| G1 | 提供稳定的本地音频转写能力 |
| G2 | 提供从录音到会议纪要的完整异步工作流 |
| G3 | 通过时间戳、原文、修正文本和任务产物支持结果复核 |
| G4 | 让用户无需修改代码即可选择或编辑纪要模板 |
| G5 | 为已审核的会议数据提供 MLX ASR 微调入口 |
| G6 | 使用本地文生图模型生成会议纪要相关图片素材 |
| G7 | 通过前端管理页降低 LLM 配置门槛 |

### 2.4 非目标

- 当前不定位为公网 SaaS、多人协作、云端存储或托管系统；
- 当前不提供账号、权限、数据隔离和审计体系，这些不属于产品需求；
- 当前不保证跨平台运行，后端依赖 Apple Silicon 与 MLX；
- 当前不把 LLM 自由改写作为默认转写纠错方式；
- 当前不承诺生产级高并发、跨任务队列调度和自动归档。

## 3. 用户与典型场景

### 3.1 目标用户

| 用户 | 核心诉求 |
| --- | --- |
| 会议参与者 | 上传录音，获得带主题和说话人的会议纪要 |
| 资料整理者 | 对逐段转写、说话人和纠错结果进行复核 |
| 团队管理员 | 维护说话人档案和样本，审核待确认声纹 |
| 模型维护者 | 从已审核数据集启动或停止 ASR 微调 |
| 个人用户 | 通过浏览器进行实时语音对话和会议整理 |

### 3.2 核心场景

#### 场景 A：实时语音对话

用户打开首页，授权麦克风并开始会话。Astra 接收音频，完成 ASR、LLM 流式推理和按句 TTS，将识别文本、回答 token 和音频片段实时返回。用户可以中断当前回答并继续下一轮对话。

#### 场景 B：普通文件转写

用户上传音频并选择“普通转写”，系统返回完整 ASR 文本，适合快速查看，不进入会议纪要或人工审核流程。

#### 场景 C：流式纠错

用户上传音频并选择“流式修正”，系统先返回 ASR 结果，再通过 SSE 发送纠错 token 和分段结果。默认以确定性规则为主；LLM 清洗只有在配置开启且满足候选约束时才参与。

#### 场景 D：生成会议纪要

用户上传会议音频，填写可选主题，选择内置或自定义提示词模板。系统立即返回任务 ID，在独立 worker 中执行完整工作流；前端通过 WebSocket 监听任务状态，完成后展示纪要和逐字稿，并保留任务目录中的原始产物。

#### 场景 E：审核与训练

用户在审核页逐段播放音频、查看原文和修正文本，提交修正或审核结果。已批准的记录可组成训练数据集，模型维护者在训练页配置参数并启动、查看或停止 MLX 微调任务。

#### 场景 F：生成会议配图

用户在会议纪要完成后输入图片描述，或基于会议主题/摘要生成图片提示词，选择本地图片模型和输出尺寸，生成会议封面或主题插图。生成结果保存到本地任务目录，可预览、重新生成并插入或下载到会议资料中。

#### 场景 G：首次配置 LLM

用户打开“管理设置”页，填写 LLM 服务地址和模型名称，可选填写 API Key，点击“测试连接”确认服务可用，再点击“保存并应用”。配置会写入 `.env`，并立即作用于实时对话和会议纪要，无需手动编辑配置文件或重启服务。

## 4. 产品流程

### 4.1 实时对话流程

```text
浏览器建立 /ws
  -> start_session
  -> LISTENING：发送 PCM 音频
  -> speech_end
  -> ASR
  -> LLM 流式推理
  -> 按句 TTS
  -> 返回文本和音频事件
  -> SPEAKING 完成后回到 LISTENING
  -> end_session / interrupt
```

会话状态为 `IDLE`、`CONNECTING`、`LISTENING`、`REASONING`、`SPEAKING`。每轮生成使用 `generation_id` 隔离，避免被中断的旧结果继续影响当前会话。

### 4.2 会议处理流程

```text
上传音频与主题/模板
  -> 创建 task_id 和任务目录
  -> 独立 worker
  -> Silero VAD
  -> MLX ASR
  -> 标点（passthrough 或 FunASR）
  -> 说话人分离（resemblyzer + Ward 聚类）
  -> 确定性纠错
  -> 分段纪要生成（本地或远程 LLM）
  -> 最终纪要合并
  -> 写入报告与元数据
```

每个片段至少保留开始时间、结束时间、原始文本和说话人信息。未匹配到正式档案的声纹进入 `pending_review`，管理员审核通过后才用于后续会议匹配。

### 4.3 文生图流程（规划）

```text
会议主题/摘要或用户图片描述
  -> 生成或编辑图片提示词
  -> 调用本地文生图模型
  -> 保存 PNG/JPEG 到会议任务目录
  -> 前端预览、重新生成或下载
```

该流程必须在本机完成，不把提示词、会议文本或生成图片发送到外部图片服务。

### 5.2 音频输入与格式

- 支持 `.m4a`、`.wav`、`.mp3`、`.flac`、`.aac`、`.mov`、`.mp4`；
- 普通会议任务最大文件大小为 500 MB；
- 说话人注册样本最大文件大小为 20 MB；
- 超过长音频阈值时，ASR 按配置的 chunk 时长切片并拼接结果；
- 音频处理失败时，任务状态必须进入失败态，并在 `status.json` 和 `job.log` 中留下可定位信息。

### 5.3 会议提示词模板

模板是会议纪要阶段的输入配置，不改变 VAD、ASR、标点、声纹分离和确定性纠错结果。

每个模板包含：

- `id`：稳定标识；
- `name`：用户可读名称；
- `description`：使用说明；
- `segment_system_prompt`：分段信息提取提示词；
- `final_system_prompt`：最终会议纪要合并提示词；
- `builtin`：是否为只读内置模板。

产品要求：

1. 上传会议时可以选择模板，默认使用标准模板。
2. 内置模板可查看但不可修改或删除。
3. 自定义模板可以新增、编辑、删除，并在下一次任务中使用。
4. 任务元数据记录实际使用的模板 ID，保证结果可追溯。
5. 模板内容为空或 ID 不存在时，接口返回明确的 4xx 错误。
6. 模板默认持久化到 `~/.astra/meeting-prompt-templates.json`，也可用 `MEETING_PROMPT_TEMPLATES_PATH` 指定路径。

建议的模板语义：

| 模板 | 适用场景 | 期望输出 |
| --- | --- | --- |
| 标准纪要 | 常规项目会议 | 摘要、议题、决策、行动项、风险和待确认项 |
| 决策追踪 | 评审或管理会议 | 聚焦决策、负责人、截止时间和阻塞项 |
| 精简纪要 | 快速浏览 | 只保留结论、行动项和关键问题 |

### 5.4 会议结果与复核

任务完成后，产品至少展示：

- 会议主题和任务状态；
- 生成的 Markdown 纪要；
- 带时间戳、说话人和文本的逐字稿；
- 任务选择的提示词模板；
- 片段原文、确定性纠错结果和可播放的片段音频；
- 失败任务的错误信息和日志路径。

复核操作包括：

- 编辑片段文本；
- 修改或确认说话人名称；
- 保存待处理修改；
- 批准或拒绝训练样本。

### 5.5 说话人管理

- 创建、查看、重命名和禁用说话人档案；
- 上传和查看说话人样本；
- 对会议中产生的待审核声纹进行改名和批准；
- 限制单场会议的最大聚类人数，默认值为 32；
- 声纹档案使用 SQLite 持久化，路径由 `SPEAKER_STORE_PATH` 配置。

### 5.6 训练控制

- 只允许使用已批准的训练数据；
- 支持配置数据集、输出目录和训练参数；
- 通过独立进程调用 `mlx-tune` 执行训练；
- 支持查询运行状态、日志摘要和输出适配器路径；
- 支持停止当前训练任务；
- 训练 JSONL 每行至少包含 `audio` 和 `text` 字段。

### 5.7 本地文生图

#### 功能目标

为会议纪要生成可选的本地图片素材，首期聚焦会议封面、主题插图和摘要配图，不改变纪要正文内容。

#### 产品要求

1. 用户可以手动输入图片描述，也可以基于会议主题或摘要生成可编辑的初始提示词。
2. 用户可以选择本地可用的图片模型、尺寸和图片数量；未配置模型时给出明确提示。
3. 系统在本机执行推理，生成 PNG 或 JPEG，并保存到对应会议任务目录。
4. 用户可以预览、重新生成、保留或删除当前生成结果；原始会议纪要和逐字稿不因配图失败而丢失。
5. 生成结果的模型、提示词、尺寸、时间和文件路径写入图片元数据或任务 `meta.json`。
6. 图片生成属于异步任务，前端显示 `queued`、`processing`、`done`、`failed` 状态和错误信息。
7. 图片生成不应默认把整篇逐字稿发送给模型；默认只使用用户确认的主题、摘要或手动提示词。

#### 首期不做

- 不做在线图片平台接入或云端图片生成；
- 不做复杂的局部重绘、蒙版编辑和图片工作流编排；
- 不保证生成图片中的文字准确，正式信息仍以会议纪要文本为准。

#### 规划接口

以下接口用于后续实现，当前版本不作为已实现接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/image/generate` | 创建本地文生图任务 |
| GET | `/api/image/{task_id}/events` | 获取生成状态事件 |
| GET | `/api/image/{task_id}` | 查看图片元数据和本地文件 |
| DELETE | `/api/image/{task_id}` | 删除生成图片及其元数据 |

### 5.8 LLM 管理设置

管理设置页面向首次使用者，不要求手动编辑 `.env`。可配置项包括服务地址、对话/模型列表路径、模型名称、API Key、请求/连接/流式超时、实时纠错和会议候选纠错参数。

产品要求：

1. 页面打开后读取当前配置，API Key 仅显示掩码和“已配置”状态。
2. 用户不修改 API Key 时，提交空值不得覆盖已有 Key；用户可以显式清除 Key。
3. 点击“测试连接”调用健康检查，并显示 LLM 连接结果。
4. 点击“保存并应用”后，配置写入项目 `.env`，当前进程立即更新，新的会议 worker 继承最新配置。
5. 保存失败时不得替换当前运行时配置，并显示明确错误。

| 页面 | 路径 | 核心能力 |
| --- | --- | --- |
| 实时助手 | `/` | 麦克风会话、状态显示、转写、LLM token、TTS 播放、中断 |
| 音频工作台 | `/upload` | 文件选择、主题输入、模板选择/编辑、普通转写、流式纠错、生成纪要、说话人管理 |

- 处理中的会议任务必须显示状态和进度反馈，不能要求用户重复提交文件；

- 说话人未审核前应有明显的待审核提醒；
- 训练启动前必须显示数据集和输出目录，避免误用未批准数据。
- 图片生成失败时不影响纪要结果，并显示本地模型配置或显存/内存相关错误。

## 8. 数据与产物

### 8.1 会议任务目录

每个任务以 `task_id` 作为独立目录，默认位于 `~/Astra/meetings/<task_id>/`，至少包含：

| 文件 | 作用 |
| --- | --- |
| `report.md` | 最终会议纪要 |
| `transcript.txt` | 逐字稿 |
| `meta.json` | 主题、模板、时间和任务元数据 |
| `status.json` | 当前状态、错误和完成信息 |
| `job.log` | worker 执行日志 |

### 8.2 状态模型

会议任务至少支持 `processing`、`done`、`failed` 三种外部可见状态。状态文件是任务恢复和故障排查的依据，前端事件流是用户界面的实时通知通道。

### 8.3 本地数据与隐私

- 原始录音、任务产物、声纹样本和图片产物默认保留在本地文件系统；
- ASR、VAD、标点、声纹分离、TTS 和文生图使用本地模型或本机服务；
- LLM 支持本地或远程 OpenAI 兼容服务。使用远程 LLM 时，仅发送纪要/对话所需的文本上下文，不发送原始音频；
- 如果 LLM 服务需要 API Key，只从环境变量读取，不能写入仓库、报告或前端响应；
- 图片提示词、模型参数和生成图片保存在本地任务目录；
- 当前版本没有自动清理策略，删除和归档策略属于后续规划。

## 9. 配置与部署要求

### 9.1 必要依赖

- macOS + Apple Silicon；
- Python 3.11；
- MLX Audio ASR 模型；
- Silero VAD 模型；
- Piper TTS voice；
- 本机运行或可由本机访问的 OpenAI 兼容 LLM 服务（本地/远程均可）；
- 前端构建和部署所需的 Node/Docker 环境。

文生图功能启用后，还需要在本机安装并配置兼容 Apple Silicon 的图片生成模型和推理运行时；具体模型选型不作为当前已实现能力承诺。

### 9.2 关键配置

| 配置 | 作用 |
| --- | --- |
| `ASR_MODEL` | MLX ASR 模型标识或本地路径 |
| `VAD_MODEL` | VAD 模型路径 |
| `TTS_MODEL_PATH` | Piper voice 文件路径 |
| `LLM_BASE_URL` / `LLM_MODEL` | 本地或远程 OpenAI 兼容 LLM 服务，可在管理设置页修改 |
| `LLM_API_KEY` | LLM 服务认证信息，可为空或按服务要求配置 |
| `PUNCTUATION_ENGINE` | `passthrough` 或 `funasr` |
| `MEETING_PROMPT_TEMPLATES_PATH` | 自定义会议模板文件路径 |
| `SPEAKER_STORE_PATH` | 说话人 SQLite 路径 |
| `ASR_LONG_AUDIO_THRESHOLD_SECONDS` | 长音频切片阈值 |
| `ASR_CHUNK_DURATION_SECONDS` | ASR 切片时长 |
| 文生图模型配置 | 本地图片模型、输出目录和推理参数（规划） |

后端必须在 Mac mini 宿主机原生运行，前端 Nginx 负责静态文件、HTTP API 和 WebSocket 反向代理。模型首次加载可能耗时较长，部署验收应包含真实音频预热。

## 10. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 易用性 | 首次使用者可通过管理设置页完成 LLM 连接配置 |
| 本地化 | 音频、语音模型、TTS、声纹、会议产物和文生图推理均在本机完成 |
| LLM 适配 | LLM 支持本地部署，也支持通过配置接入远程 OpenAI 兼容服务 |
| 隐私 | 默认本地保存数据；远程 LLM 仅接收必要文本，不设计权限和数据隔离 |
| 可追溯 | 任务记录模板、主题、状态、日志、原始文本和时间戳 |
| 可恢复 | 会议处理使用独立 worker，主 API 不被长任务生命周期绑定 |
| 可维护 | VAD、标点、ASR、声纹分离和纪要阶段通过清晰契约组合 |
| 兼容性 | 运行时以 MLX ASR 为唯一 ASR 引擎，面向 Apple Silicon |
| 可观测性 | 提供健康检查、任务状态文件、worker 日志和训练状态 |
| 输入安全 | 校验文件后缀、空文件和大小上限；不把本地服务密钥暴露给前端 |
| 测试 | 后端单元/接口测试覆盖核心流程；前端必须通过 TypeScript 构建 |

当前 MVP 不设定生产级并发和延迟 SLA。性能验收应以目标 Mac mini、目标模型和真实音频实测为准。

## 11. 验收标准

### 11.1 功能验收

1. 用户可以建立实时会话，完成一轮“录音 → ASR → LLM → TTS”，并能中断回答。
2. 普通转写能返回文本；流式转写能收到 ASR、纠错分段和结束事件。
3. 会议上传后立即返回任务 ID，任务完成后能通过事件流获知结果，并生成完整任务产物。
4. 三个内置模板可选择且不可编辑/删除。
5. 自定义模板可新增、编辑、删除，选择后会影响纪要提示词，并记录在 `meta.json`。
6. 会议片段保留时间戳和说话人信息，用户可以播放、修改和审批片段。
7. 已批准数据集可被训练页选择，训练支持启动、查看状态和停止。
8. 健康检查能区分关键依赖未配置、未加载和可用状态。
9. 文生图功能启用后，用户可以使用本地模型根据主题或提示词生成会议配图，结果可预览、保存和重新生成，且生成失败不影响会议纪要。

### 11.2 工程验收

- `PYTHONPATH=backend .venv/bin/pytest -q backend/tests` 通过；
- 前端 TypeScript 检查和 Vite 构建通过；
- `git diff --check` 无格式错误；
- 不提交真实录音、API Key 或本地模型文件。

### 11.3 真实环境验收

自动化测试只能证明接口契约、状态转换和隔离逻辑，不能替代以下检查：

- 在目标 Mac mini 上使用真实音频完成 MLX ASR、VAD、声纹分离和 Piper TTS；
- 使用配置的本地或远程 OpenAI 兼容 LLM 生成一份会议纪要；
- 验证 Nginx 代理下的 HTTP、SSE 和 WebSocket；
- 验证长音频耗时、内存占用和模型首次加载时间；
- 验证说话人样本和训练任务的真实输出。

## 13. 版本边界

当前 MVP 的完成定义是：在目标 Apple Silicon Mac mini 上，用户能够从浏览器完成实时对话或上传会议录音，得到可追溯的转写/纪要结果，并能使用模板选择、片段复核、说话人审核和训练控制能力。LLM 可按配置使用本地或远程 OpenAI 兼容服务；文生图作为下一阶段的本地扩展能力，必须在不引入云端图片服务的前提下接入。公网化、权限化、数据隔离、高并发和生产 SLA 不属于本版本发布门槛。
