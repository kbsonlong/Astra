# Astra 音色库视觉设计规范

> 更新时间：2026-10-01
> 关联文档：[页面方案](tts-voice-library-page-plan.md) · [页面线框稿](tts-voice-library-wireframes.md)
> 基础：复用现有 Astra「档案室 + 精密仪器」设计系统，不新增平行视觉语言。

## 1. 设计意图

音色库不是音乐播放器，也不是社交头像墙。它管理的是具备授权、版本和可追溯性的敏感语音资产，视觉上应传达三件事：

1. **可辨识**：用户能迅速分辨音色名称、引擎、语言、版本和可用状态；
2. **可验证**：参考音频、授权确认和试听结果必须被清晰地区分；
3. **可追溯**：revision 是一等信息，而不是隐藏在二级设置中的技术细节。

页面沿用暖纸色基底、墨蓝操作色、朱砂实时信号色，以及“衬线标题 + 无衬线界面 + 等宽数据”的排版系统。禁止把音色库做成高饱和渐变、唱片封面或人物照片驱动的娱乐化界面。

## 2. 令牌与排版

所有颜色、间距、圆角、阴影、字体和动效使用 `frontend/src/styles.css` 中已定义的语义令牌，不为音色库直接写新的固定颜色值。

| 用途 | 令牌/样式 | 使用规则 |
| --- | --- | --- |
| 页面与卡片背景 | `--bg-canvas`、`--bg-surface` | 页面保持暖纸底，卡片使用表面色。 |
| 主要可操作元素 | `--accent`、`--accent-soft` | 新建、试听、进入实时助手、当前选中项。 |
| 实时会话信号 | `--live`、`--live-soft` | 仅用于“正在通话/正在播放/实时”状态，不用于普通可用音色。 |
| 可用与授权已确认 | `--success-*` | 仅表达已通过、已授权、试听成功。 |
| 草稿与待处理 | `--warning-*` | 草稿、待确认授权、模型加载等待。 |
| 撤销与危险操作 | `--danger-*` | 撤销授权、不可逆风险说明、失败状态。 |
| 次要文本和技术数据 | `--text-tertiary` + `--font-mono` | 引擎、采样率、revision、日期、哈希摘要。 |

排版层级：

```text
页面标题：      h1 / --font-display / --text-2xl
区块标题：      h3 / --font-display / --text-lg
音色名称：      UI 600 / --text-base
正文说明：      UI 400 / --text-sm
元数据：        Mono 400 / --text-2xs
状态徽章：      UI 500 / --text-xs
```

音色名称不使用 display serif，以避免卡片密度升高；只在页面和区块标题使用衬线字体。`r3`、采样率、秒数、日期与哈希摘要始终使用等宽字体，数字采用 tabular-nums。

## 3. 导航与页面框架

“音色库”新增导航项使用现有 `.navitem` 规则，图标应为中性、可辨识的单字符或统一 SVG 线性图标。不得复用会议说话人或麦克风图标，以减少“识别说话人”和“合成音色”的语义混淆。

页面遵循现有结构：

```text
.view
  .page-head
    .eyebrow         06 · 音色库
    h1               本地音色库
    p                解释边界与用途
    .page-head__actions
  页面主体
```

主内容最大宽度继承 `.body` 的 1320px 约束。列表页在宽屏下使用三列卡片网格；不足 1080px 时降为两列，移动端单列。筛选器在移动端换行，主操作始终可见。

## 4. 音色卡片

### 4.1 尺寸与结构

推荐最小卡片宽度 260px，使用 `.card` 的 `--radius-lg` 和 `--space-5` 内边距。卡片分为：

```text
顶部：识别区（音色印记、名称、状态）
中部：元数据（引擎、语言、revision、参考时长）
底部：授权摘要与操作区
```

音色印记使用 36px 方形圆角容器：浅色背景为 `--accent-soft`，深色模式沿用同一语义令牌。首期采用名称首字或抽象波形线稿，不使用真人头像或自动生成的人像。

### 4.2 状态编码

状态必须同时具备文字、色彩和形状，不能只依赖颜色：

| 状态 | 徽章 | 卡片处理 | 主操作 |
| --- | --- | --- | --- |
| 可用 | `badge--success`，文字“可用” | 正常表面卡片 | 播放参考、试听、用于本次会话 |
| 草稿 | `badge--warning`，文字“待授权” | 保持正常对比度，不降低整体透明度 | 查看详情、确认授权 |
| 归档 | `badge--neutral`，文字“已归档” | 元数据正常，弱化操作区 | 查看详情、恢复 |
| 已撤销 | `badge--danger`，文字“已撤销” | 不隐藏卡片；操作区仅保留详情 | 查看原因 |
| 模型不可用 | `badge--warning`，文字“引擎未就绪” | 仍显示已授权状态 | 查看配置、使用系统默认 |

可用音色不应使用朱砂色；朱砂只用于会话“正在使用”或“正在播放”这一短暂实时状态。

### 4.3 交互反馈

- Hover：边框由 `--border-default` 过渡至 `--border-strong`，不使用强烈浮起效果；
- Selected：`--accent-soft` 背景与 1px `--accent-soft-border`，搭配文本“本次会话已预选”；
- Focus：复用全局 2px `--accent` 焦点环；
- Disabled：按钮使用既有 `:disabled` 样式，并紧邻显示禁用原因，不能只呈灰色；
- Playing：播放按钮显示暂停图标，并在卡片底部显示 2px 朱砂播放进度条。

## 5. 参考音频与波形

参考音频是授权资产，不应视觉上与“试听合成结果”混淆。

| 元素 | 参考音频 | 试听合成 |
| --- | --- | --- |
| 标签 | `参考录音` | `合成试听` |
| 主色 | 中性/墨蓝 | 成功后墨蓝；播放时朱砂 |
| 内容 | 原始时长、格式、采样率 | 生成耗时、引擎、模型版本 |
| 操作 | 播放、下载（仅未撤销且允许读取时） | 播放、重试、下载 WAV（仅未撤销时） |

波形使用低对比 `--border-strong` 作为静态基线，已播放部分使用 `--live`。若首期没有真实波形数据，不使用伪波形；应采用简单播放器和时长文本，避免营造不存在的音频分析能力。

播放器高度保持 36px，控制图标至少有 32px 可点击区域。时间显示使用 `00:00 / 00:09` 的等宽数字，不仅以滑块位置表达进度。

## 6. 新建向导与授权确认

### 6.1 步骤条

复用设计系统的步骤标记样式：

- 已完成：`--success` 实心圆与对勾；
- 当前步骤：`--accent` 实心圆与步骤数字；
- 未完成：`--bg-surface` 圆、`--border-default` 边框和弱化名称；
- 步骤之间连接线仅表达流程位置，不能被用作真实上传或合成进度。

窄屏下步骤条保留数字与短名称，可横向滚动，但不能只留下进度百分比。

### 6.2 上传区

沿用 `.dropzone` 的虚线边框和空状态语言。新增以下视觉反馈：

- 拖入时：`--accent-soft` 背景和 `--accent` 边框；
- 校验成功：文件卡片左侧使用 success 印记，展示格式、单声道、时长；
- 校验失败：错误信息置于文件卡片下方，以 `--danger-text` 呈现，并给出可执行修复说明；
- 不在上传区显示“高质量”“安全”等无法由程序可靠判断的绝对结论。

### 6.3 授权区

授权确认使用独立 `.card` 或 `alert--warning` 容器，左侧配文字化的“授权确认”印记，不用绿色勾选暗示授权已被系统验证。

确认勾选框的最小可点击高度为 44px。长文本可换行，勾选框与首行对齐。提交按钮文案应为“确认授权并继续”，不能简写为“下一步”。

## 7. 试听合成状态

试听是一项异步、可能较慢的模型操作。必须使用显式状态而非无意义的无限旋转图标。

```text
待生成 → 正在加载模型 → 正在构建音色 → 正在合成 → 可播放 / 失败
```

视觉规则：

- “正在加载模型”和“正在构建音色”使用 `badge--warning`；
- “正在合成”使用 `badge--accent` 和 4px 不确定进度条；
- 成功使用 `badge--success`，显示合成耗时与模型 revision；
- 失败使用 `alert--danger`，错误标题为用户语言，技术错误折叠在“查看详情”内；
- 首次模型加载可说明“首次试听通常较慢”，但不可显示未经测量的剩余时间。

试听结果卡片与参考音频卡片之间至少留 `--space-4`，并带明确标签，避免用户误听后误以为它是原始录音。

## 8. 实时助手中的音色选择

音色选择放在“开始通话”按钮上方，以便用户在授权麦克风前完成确认。

```text
字段标签：回复音色
默认值：系统默认（当前引擎）
说明：会话开始后固定音色版本，结束通话后可更换。
```

选择项由两行组成：第一行显示名称与 revision，第二行显示引擎和可靠性说明。系统默认项始终在首位，并以“当前引擎的稳定声音”而非“低质量”描述。

产品已选择多引擎路由，但在 `TTS-00A` 实现、对应引擎启用且通过用户开放门禁前，选择器仍只能显示当前可路由的音色。不得把 IndexTTS 音色显示为“可选但会回退”；用户指定的声音失败时必须保留其声音身份，而不是静默改用 Piper。

会话进行中，选择控件替换为不可编辑的信息条：

```text
当前回复：小雅 · IndexTTS MLX · r3        已固定本次会话版本
```

该信息条使用 `--accent-soft`，不能与绿色“已授权”或朱砂“正在通话”混用。若当前音色在会话中被撤销授权，信息条加上 danger 边框和“新会话不可再使用”的说明，但不暗示正在进行的会话已被悄然改音色。撤销后，音色的参考录音和试听产物不再提供新的播放或下载入口。

## 9. 动效与声音播放

动效是状态反馈，不是装饰：

- 卡片和按钮仅使用既有 `--dur-fast` / `--dur-base` 过渡；
- 合成中可使用低频、不确定进度条；
- 播放中仅播放按钮与进度条动态，不让整张卡片闪烁；
- 不增加循环声波、跳动头像或自动播放音频；
- `prefers-reduced-motion: reduce` 下所有状态仍依靠文字与图标完整传达。

## 10. 无障碍与内容规范

- 所有状态使用“颜色 + 文字 + 图标/形状”三重编码；
- 文本与背景对比度至少 4.5:1，非文本边框、图标和焦点指示至少 3:1；
- 每个播放控件提供名称，例如“播放小雅 r3 的参考录音”；
- 试听状态使用 `aria-live="polite"`，失败使用可聚焦的错误摘要；
- 禁用按钮关联可见的原因说明，不能通过 hover tooltip 才获得信息；
- 术语统一：`参考录音`、`合成试听`、`音色版本`、`授权确认`、`撤销授权`；避免混用“声纹”“克隆”“角色”“音源”。

## 11. 交付检查清单

- [ ] 不新增硬编码颜色、字体、间距或圆角；
- [ ] 浅色与深色主题均复用语义令牌并验证状态对比度；
- [ ] 卡片状态、上传校验、授权确认、试听任务和撤销风险均有文字说明；
- [ ] 参考录音与合成试听在视觉和文案上可清楚区分；
- [ ] IndexTTS 实验性与模型未就绪状态在选择前即可见；
- [ ] 移动端保留 revision、授权状态和当前会话音色；
- [ ] 通过键盘完成搜索、打开详情、试听、选择音色和撤销授权的全流程。
