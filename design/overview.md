# Astra 界面设计方案 · 任务概述

## 做了什么

为 Astra「本地会议总结助手」交付了一套完整的新界面设计方案，包含**设计系统规范**与
**五页高保真可交互原型**，覆盖浅色 / 深色双主题。

产物全部位于 `design/` 目录，两个 HTML 均为零依赖单文件，可直接在浏览器打开：

| 文件 | 说明 |
| --- | --- |
| `astra-design-system.html` | 设计系统规范，含令牌可视化、组件库全状态、无障碍标准 |
| `astra-prototype.html` | 五个页面的可交互原型，含主题切换与任务状态演示 |
| `README.md` | 设计决策、令牌对照、落地路径与已知取舍 |

## 关键决策

**1. 美学方向定为「档案室 + 精密仪器」**
通用 AI 审美的典型配方是「深蓝黑底 + 紫蓝渐变 + 霓虹青」配 Inter 字体。Astra 的产品本质
是把语音变成**可追溯的档案**——时间戳、说话人、原文与修正的对照、审核印章。因此改用暖纸色
中性底、墨蓝主色、朱砂信号色，衬线做标题、等宽做数据。既避开套路，又真的贴合
「会议记录必须可追溯」这一核心诉求。

**2. 双主题不是简单反相**
浅色「暖纸」与深色「深夜书房」是两套独立调校的语义令牌：深色不用阴影而靠表面亮度表达层级，
行高额外放宽 0.06，强调色重新取色而非直接提亮。

**3. 修掉了两个真实的对比度缺陷**
渲染验证时发现并修复：

- 深色主题下实心危险按钮用白字只有约 **2.4:1**，远低于 4.5:1。方案单独定义
  `--btn-danger-bg`，深色下取更深的红，达到 4.9:1。
- 浅色主题下几处「有色文字压同色浅底」只有 4.2–4.4:1，处于及格线边缘。统一把
  `*-text` 令牌压深一档，全部提升到 4.9:1 以上。

**4. 图形色与文字色拆成两套令牌**
WCAG 对图形要求 3:1、对正文要求 4.5:1。朱砂作为色块是 `--live`，作为文字必须是更深的
`--live-text`。组件里凡「有色文字」一律引用 `*-text` 变体。

**5. 四个签名元素**
声纹罗盘（麦克风状态即页面重心）、时间脊柱（逐字稿左侧的连续时间轴）、勘校对照
（原文划掉 + 修正并列，窄屏不崩）、朱砂印（审核状态用印章而非绿勾，形状本身区分状态）。

## 验证方式

用无头 Chrome 对浅色 / 深色下的全部五个页面逐页渲染截图检查，发现并修复了上述对比度缺陷
以及声纹罗盘的形状问题（初版径向柱穿入中心圆，视觉上像一只爪子，已重做为 16 根柱从内环
向外生长的正确径向布局）。

所有状态同时用**颜色 + 文字 + 形状**三重编码，色盲用户与灰度打印下依然可读。

## 后续建议

1. 落地按三步走：先整体替换令牌层（外观不变但获得双主题能力）→ 迁移高频组件并拆解
   1010 行的 `UploadPage.tsx` → 最后处理实时对话页的罗盘与时间脊柱。
2. **字体必须自托管**。原型为展示效果用了 Google Fonts，但产品跑在局域网，生产环境
   需自托管 Latin 子集（约 120KB），中文继续走系统字体。
3. 两个 HTML 各自内联了完整令牌块（刻意重复以保证单文件可分发性），接入真实工程时
   应合并为一份 `tokens.css`。
4. 会议配图在 PRD 中标注为规划中，本轮仅做占位处理，未设计具体交互。
