00 · Context

把语音变成可追溯的档案

Astra 是运行在个人 Mac mini 上的本地会议总结助手。音频、模型推理和会议产物全部留在本机， 用户从浏览器完成实时语音对话或上传会议录音，得到带时间戳、说话人和审核痕迹的转写与纪要。

目标用户

会议参与者、资料整理者、团队管理员、模型维护者。均为同一台 Mac mini 上的本机使用者， 不是公网多租户用户，不存在账号与权限体系。

核心任务

① 说话即得回答；② 录音变逐字稿；③ 逐字稿变结构化纪要； ④ 复核不确定的说话人与纠错；⑤ 用已批准数据微调模型。

使用情境

长时间注视高密度文本（逐字稿、日志）；等待长任务（VAD→ASR→声纹→纪要）时离开再回来； 对隐私敏感，明确知道数据没出本机。

品牌调性

档案室 + 精密仪器。 这个产品的价值不在于「很智能」，而在于「很可靠、可追溯、可复核」。 视觉上它应该像一台好的录音设备，也像一份被认真整理过的会议档案：克制、精确、有纸张的暖意， 而不是又一个发着霓虹光的 AI 面板。

◆ 我们要的

  • 暖中性纸色底，长时间阅读不刺眼
  • 衬线体承担标题，给文档以权威感
  • 等宽体承担时间戳、任务 ID、日志
  • 朱砂色作为「正在录制 / 正在处理」的信号
  • 收紧的圆角、克制的阴影，取仪器感
  • 状态永远带文字与图形，不靠颜色单独表达

◇ 我们要避开的

  • 纯黑底 + 紫蓝渐变 + 霓虹青的「AI 三件套」
  • Inter / Roboto 这类无个性的默认字体
  • 毛玻璃滥用、发光描边、无意义的火花线
  • 万物皆卡片、卡片套卡片
  • 把所有按钮都设成主按钮
  • 纯黑 #000 与纯白 #fff 的大面积铺陈
01 · Principles

五条设计原则

每一条都对应产品里真实存在的痛点，不是装饰性口号。

1 · 状态永远可见

会议任务要跑 VAD、ASR、标点、声纹分离、纠错、纪要六段。用户离开又回来时必须一眼知道 「跑到哪了、还剩什么、是不是卡住了」。进度不是一根抽象进度条，而是有名字的阶段。

2 · 证据链不断裂

每个片段都同时呈现时间戳、说话人、原文与修正文本。用户永远能回答 「这句话是谁在几分几秒说的，模型原来识别成什么，我改成了什么」。

3 · 语音是主角

实时对话页里，麦克风状态是页面的视觉重心，不是工具栏上的一个小圆点。 用户不看文字也应该知道「它在听」「它在想」「它在说」。

4 · 密度服务阅读

界面外壳用 14px 密集排版以容纳更多信息；逐字稿和纪要正文放宽到 16px、行高 1.7， 因为那是要逐字读的内容。两种密度各有各的理由。

5 · 本地就该有本地的样子

不出现云端同步、协作邀请、分享链接这类暗示数据外流的元素。字体、图标、资源全部可离线， 因为产品本身跑在局域网里。

6 · 失败必须可操作

任务失败时不给一句「出错了」，而是给出失败阶段、错误摘要和日志路径， 并把「重试」和「查看日志」作为并排的一级动作。

02 · Color

色彩系统

03 · Typography

排版系统

三个字体族各司其职，不再引入第四个。Newsreader 衬线体承担标题与纪要， 给文档以权威感；IBM Plex Sans 承担界面，带工业仪器的技术性格且不做作； IBM Plex Mono 承担一切数字——时间戳、任务 ID、时长、日志。

字体栈与离线降级

displayNewsreader → Songti SC → Noto Serif CJK SC → Georgia, serif
uiIBM Plex Sans → PingFang SC → Hiragino Sans GB → Microsoft YaHei, sans-serif
monoIBM Plex Mono → SF Mono → ui-monospace → Menlo, monospace

中文回退依赖系统字体（macOS 上是 PingFang SC / Songti SC），这在局域网离线场景下是刻意选择： 不为中文加载数 MB 的 Web 字体。若后续要统一各平台的中文观感，应自托管子集化的 思源黑体 / 思源宋体，而不是依赖 CDN。

字号阶梯

应用界面使用固定 rem 阶梯而非流体 clamp()——固定阶梯给容器布局可预测的空间， 这也是 Material、Polaris、Carbon 等主流设计系统的做法。界面基准 14px，阅读正文 16px。

04 · Space & Elevation

间距基于 4px 基准，但有节奏地跳档：组件内部用 4/8/12，组件之间用 16/24， 区块之间用 32/48/64。避免所有间距都是 16px 的均匀感——那会让界面失去呼吸的层次。

05 · Motion

动效系统

动效只用来解释状态变化，不用来表演。缓动统一使用指数型 ease-out （cubic-bezier(0.16, 1, 0.3, 1)）——起步快、收尾稳，符合物理直觉。 禁止使用回弹 / 弹性缓动，那会让一个专业工具显得轻浮。

时长令牌数值用途
--dur-instant90ms按下反馈、开关切换、颜色变化
--dur-fast140ms悬停、聚焦、徽章出现
--dur-base200ms面板展开、主题切换、标签页
--dur-slow320ms抽屉滑入、进度条推进
--dur-deliberate480ms阶段完成确认、印章落下

必须尊重 prefers-reduced-motion。 系统开启「减少动态效果」时，所有动画降至 0.01ms，仅保留状态切换的最终结果。 唯一的例外是「正在处理」的脉动指示——它承载的是「任务还活着」这一关键信息， 此时改为静态的实心圆点，而不是继续脉动。

07 · Signature

四个签名元素

这四样东西是这个界面「让人记住」的部分。它们不是装饰，各自解决一个真实的信息表达问题。

① 声纹罗盘

实时对话页的视觉重心。用同心圆刻度环 + 径向声纹柱表达麦克风状态，而不是一个发光的圆球。 刻度环呼应「仪器」，径向柱呼应「声音」。待机时刻度静止、柱体收平；聆听时柱体随音量起伏； 思考时刻度环缓慢旋转；播报时柱体反向由内向外推出。

三种状态的语言

  • 待机：外环灰色实线，内圈中性色，文字「待机」
  • 聆听中：外环变朱砂虚线，径向柱随音量跳动
  • 思考中：刻度环整体缓慢旋转，柱体收平
  • 播报中：柱体由内向外推出，颜色转靛墨

② 时间脊柱

逐字稿的左侧不是一列孤立的灰色数字，而是一条带刻度的连续时间轴——像磁带盒上的索引纸。 滚动时视觉上始终有一条「脊」把片段串起来，用户不会丢失自己在录音中的位置。

00:00:04
主持人
好，那我们就开始今天的评审。先请后端同步一下进度。
00:00:12
后端 · 曾
这周主要完成了长音频切片和拼接，超过阈值会自动分块，然后按顺序拼回来。
00:01:03
待确认声纹 #3
那我这边下周补一下真实音频的回归集。

③ 勘校对照

原文与修正文本不并排成两列（窄屏会崩），而是上下叠放：上面是划掉的原文， 下面是修正结果，各带一枚等宽体标签。这个形式借自手稿校勘，一眼就能读出「改了什么」。

那我们下周三把方案对齐一下，然后同步给市场部。 那我们下周四把方案对齐一下，然后同步给市场部。
确定性纠错 · 日期修正 · 置信度 0.94

④ 朱砂印

「已批准 / 已审核」不用绿色的对勾，而用一枚微微倾斜的朱砂方印。这是全站唯一允许出现的 装饰性倾斜——因为它表达的是「盖章」这个动作本身。印章只在审核类页面出现，用多了就失效。

实线 = 终态（已批准 / 已拒绝），虚线 = 待处理。形状本身就区分了状态， 不依赖颜色，灰度打印也能读。
08 · Accessibility

无障碍标准

目标：WCAG 2.1 AA。以下是本设计系统对开发实现的硬性要求。

要求具体做法
对比度正文 ≥ 4.5:1，大号文字与图形 ≥ 3:1，禁用态除外。有色文字一律使用 *-text 令牌。
不依赖颜色所有状态同时用颜色 + 文字 + 形状/图标三重编码。待审核是虚线框，已批准是实线框，灰度下依然可辨。
键盘可达全部交互元素可 Tab 到达，逻辑顺序与视觉顺序一致。音频播放器、片段列表、模板编辑器必须支持方向键导航。
焦点可见统一 2px 主色描边 + 2px 偏移。禁止 outline: none 而不给替代方案。
触控目标交互元素最小 44×44px 热区。图标按钮通过 padding 撑开热区，视觉尺寸可以更小。
实时区域任务状态变化通过 aria-live="polite" 播报；错误提示使用 role="alert"。转写流式追加不逐 token 播报，按句播报。
动效偏好尊重 prefers-reduced-motion，脉动指示降级为静态圆点。
缩放不设置 user-scalable=no。200% 缩放下布局不得横向溢出或截断。
表单每个输入都有真实 <label>，错误信息与输入框通过 aria-describedby 关联，错误状态加 aria-invalid。
语义结构正确的标题层级、<nav> / <main> 地标、表格使用 <th scope>。模态框开启时焦点锁定并返回触发元素。
09 · Handoff

交接说明

设计令牌以 CSS 自定义属性交付，与现有 frontend/src/styles.css 的技术栈一致， 不需要引入任何 CSS-in-JS 或预处理器。

落地路径建议
