# Astra 界面设计方案 · v1.0

面向 Astra「本地会议总结助手」的完整 UI 设计方案。两个文件均为**零依赖单文件 HTML**，
双击即可在浏览器打开，不需要构建工具或本地服务器。

## 交付物

| 文件 | 内容 | 打开方式 |
| --- | --- | --- |
| `astra-design-system.html` | 设计系统规范：设计上下文、色彩令牌（双主题对照）、排版阶梯、空间与层次、动效、组件库全状态、四个签名元素、无障碍标准、交接说明 | 直接打开 |
| `astra-prototype.html` | 高保真可交互原型：实时助手、音频工作台、会议复核、模型训练、管理设置五个页面 | 直接打开 |

两个文件都内置了主题切换按钮（右上角），可实时对比浅色 / 深色。主题选择会写入
`localStorage`，在系统偏好为深色时默认深色。

## 设计方向

**档案室 + 精密仪器。**

Astra 的产品价值不在于「很智能」，而在于「很可靠、可追溯、可复核」。用户要能回答
「这句话是谁在几分几秒说的，模型原来识别成什么，我改成了什么」。所以视觉语言参照的
是**一台好的录音设备**和**一份被认真整理过的会议档案**，而不是又一个发光的 AI 面板。

这个方向直接决定了几件事：

- **暖纸色中性底**（OKLCH 色相 55–75，彩度 ≤0.015），长时间读逐字稿不刺眼，也天然区别于
  「深蓝黑底 + 霓虹青」的通用 AI 审美。
- **衬线体承担标题**（Newsreader），给会议纪要以文档应有的权威感。
- **等宽体承担所有数字**（IBM Plex Mono + `tabular-nums`），时间轴滚动时不抖动。
- **朱砂作为信号色**（OKLCH 色相 42），只用于「正在录制 / 正在处理」。全站唯一允许出现
  装饰性倾斜的地方是审核印章——因为它表达的就是「盖章」这个动作。
- **圆角收紧到最大 14px**，刻意避开「全站 16px 圆角 + 通用投影」的气泡感。

## 色彩系统要点

令牌分两层：**原始色阶**（`--paper-*`、`--ink-*`、`--vermilion-*`）和**语义令牌**
（`--bg-*`、`--text-*`、`--accent`、`--live`…）。组件只引用语义层，切换主题时只重定义
语义层，原始色阶保持不变。

| 角色 | 浅色（暖纸） | 深色（深夜书房） |
| --- | --- | --- |
| 画布 | `oklch(0.975 0.006 75)` | `oklch(0.165 0.008 60)` |
| 表面 | `oklch(0.995 0.003 75)` | `oklch(0.205 0.009 60)` |
| 正文 | `oklch(0.200 0.013 55)` | `oklch(0.945 0.010 75)` |
| 主色（靛墨） | `oklch(0.450 0.085 248)` | `oklch(0.745 0.100 248)` |
| 信号（朱砂） | `oklch(0.550 0.170 42)` | `oklch(0.755 0.150 48)` |

### 三个容易踩的坑，方案里已经处理

1. **图形色和文字色是两套令牌。** WCAG 对图形要求 3:1、对正文要求 4.5:1。朱砂作为色块是
   `--live`（0.55），直接当文字用达不到 4.5:1，因此额外提供 `--live-text`（0.44）。
   成功、警告、失败同理，组件里凡「有色文字」一律引用 `*-text` 变体。
2. **深色主题下实心危险按钮要压暗，不是提亮。** 直觉上会把 `--danger` 在深色下调亮，
   但那样白字只有约 2.4:1。方案单独定义了 `--btn-danger-bg`，深色下反而取更深的
   `oklch(0.470 0.155 22)`，白字达到 4.9:1。
3. **深色主题不用阴影，靠表面亮度表达层级。** 直接反相浅色主题会得到一团糊。

### 对比度实测

| 前景 / 背景 | 浅色 | 深色 | AA 要求 |
| --- | --- | --- | --- |
| 正文 / 画布 | ≈13.0:1 | ≈12.7:1 | 4.5:1 |
| 次级文字 / 画布 | ≈5.6:1 | ≈8.0:1 | 4.5:1 |
| 三级文字 / 画布 | ≈4.5:1 | ≈5.5:1 | 4.5:1 |
| 占位符（复用三级） | ≈4.5:1 | ≈5.5:1 | 4.5:1 |
| 主按钮文字 / 按钮底 | ≈5.2:1 | ≈7.4:1 | 4.5:1 |
| 信号文字 / 画布 | ≈5.2:1 | ≈7.5:1 | 4.5:1 |
| 徽章文字 / 同色浅底 | ≈4.9:1 | ≈5.0:1 | 4.5:1 |
| 实心危险按钮白字 / 按钮底 | ≈4.7:1 | ≈4.9:1 | 4.5:1 |

数值按 OKLCH 明度换算相对亮度得出，用于设计阶段校验。**开发实现后请用
[WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) 对实际渲染值复测一次。**

## 排版

| 角色 | 字体栈 | 用途 |
| --- | --- | --- |
| display | `Newsreader → Songti SC → Noto Serif CJK SC → Georgia, serif` | 页面标题、纪要标题、印章 |
| ui | `IBM Plex Sans → PingFang SC → Hiragino Sans GB → Microsoft YaHei, sans-serif` | 界面、按钮、表单 |
| mono | `IBM Plex Mono → SF Mono → ui-monospace → Menlo, monospace` | 时间戳、任务 ID、日志、时长 |

字号用**固定 rem 阶梯**而非流体 `clamp()`——应用界面需要可预测的空间，这也是 Material、
Polaris、Carbon 的一致做法。界面基准 14px（密集），逐字稿与纪要正文 16px / 行高 1.7（阅读）。
深色主题下行高额外 +0.06，因为浅字压深底感知更轻。

## 四个签名元素

| 元素 | 解决的问题 |
| --- | --- |
| **声纹罗盘** | 让麦克风状态成为页面视觉重心。16 根径向柱 + 刻度环，待机时柱体收平，聆听时随音量起伏，思考时刻度环旋转。 |
| **时间脊柱** | 逐字稿左侧不是孤立数字，而是一条带刻度的连续时间轴，滚动时始终有「脊」串起片段，用户不会丢失在录音中的位置。 |
| **勘校对照** | 原文与修正上下叠放（窄屏不崩），上面划掉原文、下面给出修正，各带等宽标签。借自手稿校勘。 |
| **朱砂印** | 「已批准 / 已审核」用印章而非绿勾。实线 = 终态，虚线 = 待处理，灰度打印也能区分。 |

## 组件状态覆盖

原型与规范页均已覆盖：按钮（4 变体 × 3 尺寸 × 悬停 / 按下 / 聚焦 / 禁用 / 加载 / 选中）、
输入框（默认 / 聚焦 / 禁用 / 校验失败 / 占位符）、开关、徽章（实时会话 5 态 + 任务审核 7 态）、
进度（确定 / 不确定）、阶段步进器、提示条（4 语义）、空状态、骨架屏、波形播放器、
片段列表、勘校块、日志控制台、印章。

原型中的**「最近任务」卡片带状态切换器**（处理中 / 已完成 / 失败），可以直接看到三种
真实任务状态下的界面表现，不是静态截图。

## 落地路径建议

现有前端 `frontend/src/styles.css` 有 1524 行手写 CSS、5 个页面共约 3600 行 TSX。
建议分三步，每步都可独立验证：

1. **替换令牌层。** 把 `:root` 与 `[data-theme="dark"]` 两块整体替换进 `styles.css`，
   暂不改任何组件。此时界面外观基本不变，但已经具备双主题能力。
2. **迁移高频组件。** 先做按钮、输入、徽章、进度四类，再拆 `UploadPage.tsx`
   （1010 行，最重的一个）为独立组件。同步在 `index.html` 加主题初始化脚本。
3. **处理实时对话页。** 接入声纹罗盘与时间脊柱，这两处是设计上最重的改动。

## 已知取舍

- **字体**：原型为了展示效果从 Google Fonts 加载了 Newsreader 与 IBM Plex。
  **生产环境必须自托管这三个字体文件**（Latin 子集合计约 120KB），中文继续走系统字体
  （macOS 上是 PingFang SC / Songti SC）。产品跑在局域网里，不能假设有外网。
- **令牌重复**：两个 HTML 各自内联了完整令牌块，是为了保证单文件可分发的刻意重复。
  接入真实工程时应合并为一份 `tokens.css`，避免两处漂移。
- **会议配图**：PRD 中标为规划中，原型按「占位 + 规划中徽章」处理，未设计具体交互。
- **未做**：不涉及账号、权限、协作、云端同步等非目标能力，界面中也不出现任何暗示
  数据外流的元素。
